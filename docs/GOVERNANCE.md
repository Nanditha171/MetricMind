# MetricMind — Governance & Security Safeguards

MetricMind implements multi-layered security and governance rules:

## 1. Direct SQL Injection Defense
- Natural language prompts pass through AST & Regex pattern matching to reject raw SQL statements (e.g., `DROP TABLE`, `DELETE FROM`, `UPDATE SET`).
- The LangChain Agent is architected so it **cannot write SQL**. It can only pass structured JSON specifications (`SemanticQueryRequest`) to the Governed Semantic Engine.

## 2. Semantic Dictionary Validation
- Every requested measure or dimension in a query request is strictly checked against the authoritative `METRICS_DICTIONARY` and `DIMENSIONS_DICTIONARY`.
- Attempts to query invalid or unapproved metrics (e.g. `arbitrary_profit`) are rejected immediately with guidance on available metrics.

## 3. Query Execution & Row Caps
- Governed queries are hard-capped at **1,000 maximum rows** to prevent expensive memory exhaustion or warehouse cost spikes.
- Agent reasoning loops are capped at **5 maximum iterations** per user request.

## 4. Query Transparency
Every user response includes full transparency metadata:
- Exact JSON payload sent to the Semantic Layer API.
- Governed SQL statement generated by the semantic model.
- Authoritative mathematical metric formulas applied.
- Execution time (ms) and row count scanned.
